**Дата:** 2026-08-07  
**Кто чинит:** код виджета (блок D).  
**Связь:** `MASTERPLAN.md` (UI/CSS); блок D — auto-popup resume.

---

## Симптом (Алиса)

- Работает на сайте, **не нажимает** на бота.
- Попап **резко открывается в центре** экрана.
- Внутри уже **результат** (предварительная оценка / ответ), а не стартовый экран.
- Особенно при **обновлении страницы** — «невозможно находиться, теряем людей».

Это **центральный overlay** виджета (не зелёная кнопка снизу и не exit-баннер справа сверху).

---

## Диагноз (по коду, без правок)

Цепочка уже в продукте:

1. Сессия пишется в `localStorage` (`ecoleadbot_session`, TTL ~180 дней) с полем `current_screen` (например `mini_result`, `rag_answer`, `contact`…).
2. При каждом заходе на сайт `setupAutoTriggers()` (`widget/src/21-auto-popup.js`):
   - через **~45 с** (`popupDelayMs`) → `openPopup("auto_popup")`;
   - или при скролле ~50% → `openPopup("scroll_popup")`.
3. `openPopup` → `routeOnOpen()` (`13-popup.js`) **восстанавливает последний экран** из сессии (Frontend «session resume»).
4. Итог: автооткрытие + resume = **центр экрана сразу с мини-оценкой/ответом**.

Почему cooldown (60 мин после закрытия) **не спасает при F5**:

- `popup_closed_at` ставится только в `closePopup()`.
- Если страницу **обновили / ушли**, пока попап был открыт, `beforeunload` сохраняет `partial`, но **не** ставит cooldown.
- На следующем заходе `inCooldown()` = false → таймер снова открывает попап → снова результат.

**Вывод:** баг/поведение **на нашей стороне**. Андрею — только если нужен мгновенный выключатель до выката фикса.

---

## Цели фикса

1. Пока пользователь **сам не кликнул** виджет/CTA — центральный попап **не** вылезает с середины сценария.
2. Автотриггеры (время/скролл), если оставляем, открывают только **чистый intro**, либо **отключены на проде**.
3. Resume середины опроса — только по **явному** открытию (клик по кнопке).
4. Обновление страницы с открытым попапом не должно снова автооткрывать его через 45 с без клика.
5. Проверка на главной `ecolusspb.ru` (в т.ч. под админкой Bitrix у Алисы).

## Варианты решения

### Вариант 0 — быстрый обход (Андрей, 5 минут)

В `elb-config.js` / `ECOLEADBOT_SITE_CONFIG`:

```js
enableAutoPopup: false
```

Отключает time/scroll auto-open и exit-баннер (они завязаны на тот же флаг).  
Виджет по клику на зелёную кнопку продолжает работать.  
**Не заменяет** код-фикс, но сразу снимает «невозможно на сайте».

### Вариант 1 — правильный продуктовый фикс (наш код, рекомендуется)

| # | Изменение |
|---|-----------|
| D1 | **Не вызывать** `openPopup` из auto/scroll, если `current_screen` не `idle` / нет «свежей» сессии без прогресса — resume только по клику пользователя. |
| D2 | Либо жёстче: на проде **выключить** time+scroll auto-open по умолчанию; оставить только клик (+ опционально exit-баннер отдельно). |
| D3 | В `beforeunload`: если overlay открыт → выставить `popup_closed_at` (или закрыть логически), чтобы cooldown срабатывал после F5. |
| D4 | При auto-open всегда `renderIntro()` / сброс экрана в idle для автотриггера — **не** `routeOnOpen` resume (если auto всё же оставляем). |
| D5 | Bump версии, деплой, Андрею `?v=`; Алисе — как проверить (очистка localStorage один раз опционально). |

**Рекомендация оркестратора:** D1 + D3 (+ D2 для прода как дефолт `enableAutoPopup: false` или раздельные флаги `enableTimePopup` / `enableScrollPopup` / `enableExitBanner`).

### Вариант 2 — не делать

«Это фича resume» — **отклонить**: Алиса явно теряет людей; автооткрытие середины сценария неприемлемо.
