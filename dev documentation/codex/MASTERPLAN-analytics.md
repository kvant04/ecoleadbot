## TL;DR

Виджет **уже** технически считает и отправляет ~50 разных событий (открытия, просмотры экранов, клики, шаги квиза, RAG, отправка лида, ошибки) в `window.dataLayer` — это стандартный формат для Google Tag Manager. Проблема не в отсутствии кода в боте, а в том, что:

1. На сайте `ecolusspb.ru` уже стоит **GTM-5RDNGCX** и счётчик **Яндекс.Метрики 22994308** (это ставил кто-то до нас — не мы, не АС по нашей части).
2. Но эти события `ecoleadbot_*` внутри GTM **никто не подхватил** — не настроены триггеры/теги, которые превратили бы «событие в dataLayer» в «цель в Метрике» или «событие в GA4».

Поэтому по факту метрики «нет», хотя данные для неё уже есть.

## Что уже есть в коде (соответствует функциональности)

`widget/src/07-analytics.js` — функция `track(event, data)`:

```js
function track(event, data) {
  window.dataLayer = window.dataLayer || [];
  var payload = { event: "ecoleadbot_" + event };
  if (data) Object.keys(data).forEach(function (k) { payload[k] = data[k]; });
  window.dataLayer.push(payload);
}
```

Вызывается по всему виджету (**41 файл-независимых точки, ~50 уникальных событий**), покрывает весь функнел:

| Категория | Примеры событий |
|---|---|
| Открытия / показы | `widget_loaded`, `widget_opened` (с `entry_type`: floating_widget / auto_popup / scroll_popup / exit_popup / inline_cta), `popup_shown`, `popup_closed` |
| Просмотры экранов | `document_directions_viewed`, `mini_teaser_viewed`, `mini_result_viewed`, `contact_form_viewed`, `rag_question_viewed`, `final_screen_viewed`, и т.д. (десятки `*_viewed`) |
| Клики / выбор | `document_direction_selected`, `document_service_selected`, `inline_cta_clicked`, `client_gate_edit_answers`, `final_media_click` |
| Прогресс квиза | `quiz_started`, `question_answered` (id вопроса) |
| RAG | `rag_question_submitted`, `rag_answer_received`, `rag_answer_error`, `rag_feedback_positive` |
| Лид / конверсия | `lead_submitted`, `lead_submit_error`, `contact_blocked_already_submitted` |
| Exit-intent | `exit_banner_shown`, `exit_banner_dismissed` |

**Вывод:** инструментация в коде готова и достаточно подробная. Расширять список событий сейчас не приоритет — приоритет: **довести данные до отчёта**, который увидит Алиса.

## Что не сделано (разрыв)

1. **GTM-триггеры/теги не настроены.** Никто не создал в GTM (GTM-5RDNGCX) Custom Event триггер `event equals ecoleadbot_widget_opened` (и т.п.) → тег GA4/Метрика. Это конфигурация внутри интерфейса Google Tag Manager — **не в нашем репозитории**, нужен доступ к GTM-аккаунту сайта.
2. **Не подтверждено, что реально нужно Алисе:** отчёт в Яндекс.Метрике («Цели»), в GA4, или простой дашборд/таблица (например, суммарные счётчики по n8n/Bitrix).
3. **Нет прямой (не через GTM) отправки в Яндекс.Метрику.** Если у команды нет уверенного доступа/навыка в GTM (а по словам Алисы — АС не знает, как настроить), надёжнее сделать **независимый от GTM** путь: звонить `ym(COUNTER_ID, 'reachGoal', 'ecoleadbot_...')` прямо из `track()`, если `window.ym` есть на странице. Тогда цели появятся в Метрике без единого доступа к GTM — Метрика сама подхватывает произвольные `reachGoal` как «Цели JavaScript-событие».
4. **Нет документа/инструкции «как читать метрики бота»** для Алисы — куда смотреть, что означает каждая цифра.
5. **Нет автоматической текстовой сводки на почту** (Олег хочет не заходить в саму Метрику).

## Варианты решения (нужно выбрать)

### Вариант 1 — Прямые цели в Яндекс.Метрику (код, наша сторона, без доступа к GTM)

- В `track()` добавляем: если `typeof window.ym === "function"` и задан `ECOLEADBOT_CONFIG.yandexMetrikaCounterId` (или автоопределение counter id со страницы) → `window.ym(counterId, "reachGoal", "ecoleadbot_" + event, data)`.
- Плюсы: не требует доступа к GTM/GA4; Алиса получает отчёт в Метрике («Цели» → JS-события) уже при следующем деплое.
- Минусы: считает только в Метрике, не в GA4 (если он вообще используется).
- Риски: нужно не заспамить Метрику десятками мелких целей — стоит выбрать **ключевые** 8–12 событий для целей (открытие, старт квиза, mini_result, contact_form_viewed, lead_submitted, rag_question_submitted), остальное — опционально позже.

### Вариант 2 — Донастройка GTM (не код, конфигурация в вебе)

- Мы пишем Андрею/Алисе подробную инструкцию (или делаем сами, если дадут доступ к GTM-5RDNGCX): создать Custom Event триггеры на `ecoleadbot_*` → тег GA4 event / Метрика Goal.
- Плюсы: расширяемо, попадает и в GA4, и в Метрику, стандартный подход.
- Минусы: нужен доступ и время у человека, который умеет работать в GTM (сейчас такого явно нет — АС не знает).
