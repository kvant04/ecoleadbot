## 1. Продуктовая формула

**EcoLeadBot = лид на первую покупку услуги** с понятной областью, конкретной потребностью (или пакетом услуг) и предметом разговора для админа / MZS.

- Не «прогрев в ЭС».
- ЭС — вторичная продажа и база сегментов.
- **KPI:** качество лида важнее CR квиза.
- Каталог в боте — **не витрина сайта**, а **маршрутизатор к 1+ услугам** (услуги связаны между собой, пользователь выбирает направление → услугу → при необходимости связанные шаги).

**v1.4 core (бывший backlog п.19):** полный каталог услуг + маршрутизация по веткам. Это **не экспертная система** — RAG не считает, не диагностирует и не подменяет квалификацию; он кормит основной сценарий.

## 2. Ограничения UX

| Параметр | Значение |
|----------|----------|
| Экранов на прохождение | **желательно ≤ 10**, **максимум 15** |
| Приоритет | меньше экранов → выше CR; при нехватке — пересмотр структуры, не раздувание «на всякий случай» |
| Глубина | вариант Б: ветки по услуге, только ключевые уточнения (баланс потребности и CR) |

## 3. Архитектура входов

```
Intro
│
├── [1] «Понять, что нужно по экологии»
│       (= «Не знаю, с чего начать» — одна и та же первая кнопка, основной квалификационный flow)
│       → объект → ветки по признакам → мини-оценка → [RAG «Подробнее»] → контакты
│
├── [2] «Нужна конкретная услуга / документ»
│       → направление → услуга из каталога → НВОС (обяз.) → площадки → контакты
│       (без «Не знаю, что именно нужно» внутри этой ветки)
│
└── [3] «Есть вопрос?» (вторичная ссылка, не равная по весу главной кнопке)
        → RAG → мягкий мост на консультацию / основной flow
```

**RAG:** оставить на тест команде и посетителям сайта; в production — под «Есть вопрос?»; не заменяет квалификацию.

**VK / MAX в контактах:** MVP+1 (архитектура n8n / Bitrix).

**«Пройти заново»:** только для тестовой сборки, не в production.

**Защита от повторной отправки:** в production.

## 4. Основной flow (кнопка 1)

### 4.1. Intro
- CTA: **«Понять, что нужно по экологии»**.
- Текст: **«Прохождение опроса займёт 2 минуты…»**.

### 4.2. Вид деятельности
- В UI и Bitrix: **«Вид деятельности»** (не «Сегмент»).

### 4.3. Что на объекте
- **Заголовок:** «**Что из этого есть у вас на объекте?**»
- **Подсказка:** «отходы, выбросы, сбросы, особенности площадки».
- **UI:** у пунктов с пояснением — **основная строка** + **мелкая подпись** (`.ecoleadbot-card__note`); дублирование текста в заголовке не допускается.

| Пункт чеклиста (основная строка) | Подпись мелким |
|----------------------------------|----------------|
| Мусор и упаковка | ТКО — твердые коммунальные отходы |
| Производственные отходы | масла, ветошь, остатки материалов |
| Выбросы в атмосферу | |
| **Сброс воды в канализацию** | сброс в ЦСВ (централизованные сети Водоканала) |
| **Сброс воды в водные объекты** | сброс в реки, озера, моря — не в ЦСВ |
| Скважина / недропользование | |
| Спецтехника / транспорт / парковка | |
| Кухня | (приготовление пищи) |
| Сельское хозяйство | животные, продукция |
| Импорт / производство товаров и/или упаковки | РОП — расширенная ответственность производителя (импортера), экологический сбор |
| **Не знаю / ничего из перечисленного** | один пункт; id `__uncertain__`; взаимоисключающий с остальными |

**Логика «неопределённости»:** для большинства лидов «не знаю» и «ничего из перечисленного» — одна корзина. Выбор объединённого пункта:
- снимает остальные галочки;
- не даёт выбрать другие пункты, пока он активен;
- в payload: `object_signal_ids: ["__uncertain__"]`, `object_signal_uncertain: true`;
- мини-оценка → fallback «Общая оценка»;
- мини-оценка → fallback «Общая оценка».

Условные ветки по выбранным пунктам — без лишних экранов (укладываемся в лимит п.2).

### 4.4. Квалификация потребности (обновлено 11.06.2026)

Четыре вопроса **в основном flow**:

| # | Вопрос | Зачем |
|---|--------|--------|
| 1 | **Кто сейчас занимается экологией?** | Штат / аутсорс / никто |
| 2 | **Что для вас сейчас актуально?** | 6 вариантов (объединены «Что происходит?» + «Что беспокоит?») |
| 3 | **Когда хотите решить вопрос?** | Срочно → месяц → квартал → в этом году |
| 4 | **Что было бы для вас удобнее?** | Сам / подсказка / документ / аутсорс |

Порядок: чеклист → п.1–2 → категория НВОС *(если триггер)* → площадки → п.3–4 → мини-оценка.

### 4.5. Категория НВОС (п.8 — зафиксировано)
- **В ветке «конкретная услуга / документ»:** обязательно.
- **В основном flow:** опционально **или** показывать только если отмечены выбросы / сбросы / признаки НВОС.

### 4.6. «Что беспокоит?» — **снято**
Объединено с п.2 §4.4 (`main_situation`). Scoring сложности — без отдельного экрана.

### 4.7. Ценность до контактов (п.7 + п.7.1)
Часть **основного flow**, не отдельный сценарий:

```
Опрос → Предварительная оценка по блокам (зоны, без сумм штрафов)
        ↓
   [Подробнее] → короткий RAG-ответ из KB
        ↓
   «Получить консультацию» / «Вернуться к оценке»
        ↓
   Контакты
```

- Кнопка: **«Посмотреть предварительную оценку»** (не «во многих компаниях…»).
- AI summary для менеджера: не «проблемы», а **«На объекте есть / области для проверки»**.

### 4.8. Финальный экран
- Честный текст: **без** «мы подготовим письменные рекомендации», если их нет.
- Усилить текст **ЭкоКомпас** на экране «Спасибо».

## 5. Ветка «Конкретная услуга / документ» (кнопка 2)

1. Выбор **направления** (см. §6).
2. Выбор **услуги** из каталога.
3. **Категория НВОС** — обязательно.
4. Количество площадок / объектов.
5. При необходимости: 2–4 ключевых уточнения по услуге (вариант Б, не полный опрос).
6. Контакты.

Внутри ветки **нет** пункта «Не знаю, что именно нужно» → такой пользователь идёт в кнопку 1.

## 6. Каталог услуг — направления (v1.4)

**Исключено из бота:** аутсорсинг охраны труда и любые чисто OT-услуги.

**Объединённые направления (не дробить в UI):**

| № | Направление | Что входит |
|---|-------------|------------|
| 1 | **ОТХОДЫ** | ТКО, паспорта, инвентаризация, НООЛ, журналы, лицензия на перевозку, договор с региональным оператором, кадастр отходов, перевод отходов в продукцию, **РОП / экологический сбор** *(платёж производителей/импортёров за утилизацию товара после выбытия из обращения)* |
| 2 | **ВОЗДУХ** | выбросы, ИИВ, ПДВ/НДВ, СЗЗ, паспорт ГОУ, ДВОС, план НМУ |
| 3 | **ВОДА** | сбросы (ЦСВ и собственный), НДС, баланс водопотребления, декларация сточных вод, ЗСО, санэпидзаключение на водный объект, **лицензия на воду (недра)** |
| 4 | **НВОС: учёт, отчётность и экосопровождение** | постановка на учёт → отчётность, 2-ТП, ПЭК, аудит/диагностика, обучение, экосопровождение (одна услуга) — по отдельности или комплексом |
| 5 | **КЭР и ГосЭкоЭкспертиза (ГЭЭ)** | сложные разрешительные услуги: КЭР, ГосЭкоЭкспертиза (ГЭЭ), санэпидзаключение на приаэродромную территорию *(узкий сегмент — аэродромы)* |

**Логика направления 4 (НВОС):** типовая цепочка — **сначала постановка на учёт**, затем отчётность и сопровождение. В боте это не жёсткий wizard, а **подсказка порядка** + выбор конкретной услуги или комплекса.

**UX направления 4 (1 доп. экран, если влезает в лимит):**
1. «Объект уже на учёте в реестре НВОС?» — Да / Нет / Не знаю  
2. Если **нет** → акцент на «Постановка на учёт» + связанные услуги.  
3. Если **да** → «Что нужно сейчас?» — отдельная услуга (2-ТП, ПЭК, расчёт платы за НВОС…) **или** экосопровождение (комплекс).

Если экран не помещается в лимит 15 — один список услуг с группировкой: **«Сначала»** (постановка на учёт) | **«Отдельно»** (2-ТП, ПЭК, плата за НВОС) | **«Комплекс»** (экосопровождение).

**Правила нормализации каталога (сайт → бот):**

| На сайте | В боте |
|----------|--------|
| 3 страницы «Экосопровождение» (общее / непищевое / строительство) | **1 услуга** «Экологическое сопровождение» *(сегмент — для SEO сайта, не для выбора в боте)* |
| «Экологический аудит» и «Быстрая диагностика по экологии» (KB) | **1 услуга** «Экологический аудит / быстрая диагностика» |
| «Лицензия на воду», «Проект геологического изучения недр», «Полевые испытания» | **1 услуга** «Лицензия на воду (недра)»; этапы — в `related_services`, не отдельные пункты |
| «Санэпидзаключение на приаэродромную территорию» | блок **КЭР и госэкспертиза** *(не ВОЗДУХ)* |

**Есть на сайте, но не отдельный пункт в боте** — только как `related_services` или уточнение менеджеру:

- Проект геологического изучения недр
- Полевые испытания и оценка запасов недр
- Страницы экосопровождения по сегментам (непищевое / строительство)

**Есть в `kb/services.md`, отдельной страницы на сайте нет** — в v1.4 **не включаем**:

- Организация общественных обсуждений (госэкоэкспертиза) — этап внутри сложных услуг, не отдельный выбор

**Вне scope EcoLeadBot (не делаем):**

- Допуски СРО
