# EcoLeadBot — ручные тесты (v1.4)

Предусловия:

1. `.env` содержит `OPENAI_API_KEY`, `OPENAI_VECTOR_STORE_ID`, `OPENAI_MODEL`.
2. Backend запущен: `py server.py` → http://127.0.0.1:8000
3. Ctrl+F5 в браузере после обновления `app.js`.
4. VPN включён, если OpenAI API недоступен из региона.

---

## Сценарий A — стартовый экран

1. Открыть http://127.0.0.1:8000
2. Нажать зелёную кнопку «Понять, что нужно по экологии» (логотип ЭУ слева)
3. **Ожидание:** intro с кнопками:
   - **Понять, что нужно по экологии** — основной flow
   - **Нужна конкретная услуга / документ** — ветка каталога (32 услуги)
   - **Есть вопрос?** — RAG
4. В шапке popup — логотип ЭУ слева сверху

---

## Сценарий B — основной flow + мини-оценка

1. «Понять, что нужно по экологии»
2. Пройти: вид деятельности → чеклист объекта → *(уточнения)* → квалификация (эколог, ситуация, срочность, формат)
3. **Ожидание:** тизер «Посмотреть предварительную оценку»
4. На экране оценки — блоки по зонам (отходы, воздух, …) + кнопка **«Подробнее»**
5. «Подробнее» → RAG → «Вернуться к оценке» / «Получить консультацию»
6. «Получить консультацию» → Contact Screen → отправка

---

## Сценарий C — ветка «конкретная услуга»

1. «Нужна конкретная услуга / документ»
2. Направление → услуга → *(при необходимости: НВОС / реестр / площадки)* → 2–3 вопроса по услуге
3. Contact Screen → отправка
4. **Ожидание:** в payload `v14.selected_service_id`, `v14.service_title`, `v14.qualification_answers`

Проверить минимум 2 услуги из разных направлений (например, отходы и НВОС).

---

## Сценарий D — RAG «Есть вопрос?»

| # | Вопрос | Ожидание |
|---|--------|----------|
| 1 | Нужно ли делать ПЭК для небольшого производства? | Ответ + источники; `answer_only` или `offer_consultation` |
| 2 | Сколько стоит экологическое сопровождение? | Ответ по services.md / company_profile.md |
| 3 | Как приготовить борщ? | Экран **«В базе пока нет готового ответа»** (`out_of_scope`, без источников) |
| 4 | Проверь мой документ | Отказ + предложение консультации |

Для каждого успешного ответа:

1. Экран загрузки «Ищу ответ в базе знаний…»
2. Ответ + блок «Источник:» (если есть sources)
3. «Это помогло ответить на ваш вопрос?»

---

## Сценарий E — ошибки RAG

| Ситуация | Экран |
|----------|--------|
| Вопрос вне базы / без источников | **«В базе пока нет готового ответа»** — «Задать другой вопрос» / «Связаться со специалистом» |
| Остановлен `server.py` или сбой API | **«Не удалось получить ответ»** (техническая ошибка) — «Попробовать ещё раз» |

---

## Сценарий F — лид и payload (n8n)

1. Отправить тестовую заявку из любого сценария
2. В консоли браузера: `[EcoLeadBot] payload →`
3. **Ожидание в payload:**
   - `v14.es_scoring` — `status`, `status_label` (при малом объёме данных: «Требует доqualification»)
   - `v14.bitrix_comment` — блоки «Характеристика объекта» + «Цель обращения»
   - `contact.comment` — Bitrix-блок + RAG (если был) + комментарий пользователя
   - `answers.activity_type` — «Вид деятельности»
   - при RAG: `answers.rag_question`, `answers.rag_answer_summary`

4. Проверить, что лид дошёл до Bitrix (webhook n8n без изменений должен принять payload; новые поля — в `v14.*`).

## API-тест (curl)

```bash
curl -X POST http://127.0.0.1:8000/api/rag/ask \
  -H "Content-Type: application/json" \
  -d "{\"question\":\"Нужно ли делать ПЭК для небольшого производства?\",\"session_id\":\"eco_test_001\",\"page_url\":\"http://127.0.0.1:8000/\",\"page_title\":\"Test\",\"page_type\":\"seo_article\"}"
```

**Ожидание:** JSON с `"status":"ok"`, `"answer"`, `"sources"`, `"assistant_recommendation"`, `"confidence"`.

## Что не входит в этот чеклист

- Автоматическое создание лидов из RAG без Contact Screen (запрещено scope)
- Полная настройка n8n под все поля `v14.*` (отдельная задача интеграции)
